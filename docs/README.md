# ARGOS 로봇 백과사전 (docs/)

분류: **Prototype**, 목표 등급 **9.5점** (실제로 쓸 수 있는 한 페이지 백과사전). 시각 규약은 [`DESIGN.md`](DESIGN.md)(Technical Folio: 그래파이트, 신호 황색, Pretendard)를 따릅니다.

## 왜

경영 리더와 지식 노동자가 휴머노이드 로봇 뉴스를 읽을 때 "무엇이 실제 진전이고 무엇이 시연인지" 스스로 판단하게 돕는 한 페이지 레퍼런스입니다. 동시에 "데이터 → 섹션 조각 → 빌드" 구조를 남겨, 다음 주제 백과사전도 같은 방식으로 만들 수 있게 합니다.

## 어떻게

### 고치는 순서: 데이터 → 조각 → build.py

1. **사실·숫자를 바꿀 때**는 먼저 `data/*.json`을 고칩니다. 정본에 없는 숫자, 날짜, URL, 실명은 쓰지 않습니다.
2. **화면을 바꿀 때**는 해당 `src/0N-*.html` 조각을 고칩니다. 조각 안의 `<script type="application/json">` 블록은 data 정본의 사본이며 손으로 고치지 않습니다. `build.py`가 빌드할 때마다 정본을 사본으로 덮어씁니다(대응표는 `build.py`의 `INLINE`). 02 조각 머리의 통계 카드와 본문 단락처럼 HTML에 직접 쓴 숫자는 정본과 함께 고칩니다.
3. 빌드합니다.

```bash
cd docs
python3 build.py           # data → 조각 인라인 JSON 동기화, index.html 생성, 점검 결과 출력
python3 build.py --check   # 생성 없이 점검만. 정본과 사본 불일치, '~한다(…).'·'~나?' 문체, 스코프 밖 선택자를 잡습니다 (문제가 있으면 exit 1)
```

4. 확인합니다. 폴더 상위에서 `python3 -m http.server 8765 --bind 127.0.0.1` 을 띄우고 `http://127.0.0.1:8765/docs/index.html` 을 엽니다. 콘솔 에러 0, 1200px과 375px에서 가로 스크롤 없음이 합격선입니다.

### 조각 규약 (새 섹션을 넣을 때)

- 파일 하나 = `<section id="섹션id" class="sec" data-nav="네비 라벨">` + `<style>` + `<script>`.
- 모든 CSS 선택자는 `#섹션id`로 시작합니다. 색과 글꼴은 셸의 `var(--토큰)`만 씁니다.
- 스크립트는 IIFE 또는 module. 전역 변수를 만들지 않습니다.
- GSAP, ScrollTrigger, Three.js는 셸이 한 번만 로드합니다. 조각에서 다시 로드하지 않습니다 (`build.py`가 잡아냅니다).
- `ScrollTrigger.refresh()`는 셸이 load와 폰트 준비 뒤 **한 번** 호출합니다. 조각은 load/fonts 시점에 refresh를 걸지 않고, 아코디언이나 탭처럼 높이가 바뀌는 상호작용 뒤에만 호출합니다.
- 고정 위치 요소(sticky, pin)는 네비 높이 `var(--nav-h)`(데스크톱 64px, 모바일 56px) 아래에서 시작합니다.
- 네비 라벨은 `data-nav`에서 자동으로 만들어지고, 첫 섹션은 로고 링크가 됩니다.
- 문체는 "~입니다/~합니다"체로 통일합니다. 줄표 대신 쉼표, 마침표, 괄호를 씁니다.

### 셸이 제공하는 것

- 토큰: `--bg --bg-2 --surface --surface-2 --line --line-2 --text --muted --dim --accent --accent-2 --steel --danger --ok --radius --ease --f-display --f-body --f-mono --nav-h --gutter`
- 유틸: `.overline` `.h-display` `.lead` `.wrap` `.reveal`(화면에 들어오면 페이드 + 24px 상승, 0.9s) `.sr-only`
- 런타임: 현재 섹션 하이라이트, 진행 바, pin 여백을 계산한 앵커 이동, 모든 ScrollTrigger의 문서 순서 정렬 후 단일 refresh
- 히어로 로딩: 01 조각이 실제 진행률(three.js 다운로드, WebGL 준비, 부품 생성, 셰이더 컴파일)을 0~100%로 보여 줍니다. 부품 생성은 32ms 단위로 쪼개 프레임을 양보하고, 백그라운드 탭에서는 쪼개지 않습니다. 셸의 단일 refresh는 `window.__heroReady`(히어로가 pin을 만든 뒤 해제)까지 기다리고, 로딩 중에는 페이지 스크롤을 잠급니다(최대 15초)
- 섹션 배경: 셸이 섹션별 그라디언트를 소유합니다(앞 섹션의 끝 톤 = 다음 섹션의 시작 톤). 조각은 섹션 루트에 background를 지정하지 않습니다.
- 푸터 출처: `build.py`가 `data/anthropic.json`(리서치 원문, PDF, 데이터)과 `data/videos_*.json`(업체별 공식 채널 영상 1건)에서 채웁니다.

## 갱신 기준

| 항목 | 주기 | 기준 |
|---|---|---|
| 영상 (`videos_*.json`, 05 조각) | 월 1회 | 업체 공식 채널의 최신 공식 영상으로 교체. 업로드일과 조회수 갱신. 임베드 불가 영상은 링크만 둡니다 |
| 업체 스펙·마일스톤 | 분기 1회, 또는 주요 발표 직후 | 제조사 공식 발표 우선. 회사 발표치는 "독립 검증 전"으로 표기 |
| 업체 추가·삭제 | 발생 시 | `videos_*.json`에 항목을 넣고 빌드합니다. 업체 수는 04 조각이 data에서 자동 계산합니다. 다른 조각에는 업체 수를 손으로 쓰지 않습니다 |
| Anthropic 리서치 (06 조각) | 원문 개정 시 | `anthropic.json`의 `is_exact` 규칙 유지. 그래프에서 읽은 근사치는 근사로 표시 |
| 산업 통계 (02 조각, IFR 등) | 연 1회 (IFR World Robotics 발표 후) | 출처 기관명과 기준 연도를 함께 표기 |

사실 검증은 갱신할 때마다 숫자 하나당 출처 하나를 확인합니다. 출처가 없으면 그 숫자를 지웁니다.

## 실패 조건과 중단 기준

- 콘솔 에러가 1개 이상이거나, 375px에서 가로 스크롤이 생기면 배포하지 않습니다.
- 3개월 넘게 영상과 스펙을 갱신하지 못하면 "보관본"으로 내립니다. 화면에는 기준일을 표시하지 않으므로, 갱신일은 data의 `generated`와 이 README에 남깁니다.
- 섹션이 늘어 페이지가 무거워지면(빌드 결과 1MB 초과) 새 섹션을 더하기보다 기존 섹션을 줄입니다.

4. 반복 가능성이 확인되면 셸과 `build.py`를 "주제 백과사전 템플릿"으로 분리해 Core Asset 후보로 올립니다.

히어로 로봇은 `src/01-hero.html`의 절차적 Three.js 모델입니다(외부 3D 파일 없음). 형태를 고칠 때는 아래 루프를 따릅니다.

## 윤문 안전장치

문장을 고친 뒤에는 원본과 대조해 사실 토큰이 그대로인지 확인합니다.

```bash
python3 tools/yunmun_guard.py <원본.html> <수정본.html>
```

숫자, 영문 토큰, URL, 태그 수, 인라인 JSON 파싱을 비교하고 하나라도 다르면 실패합니다. 문체 기준은 `korean` 스킬(AI 문체 18패턴, 종결체 통일, 숫자·고유명사 보존)을 따릅니다.
