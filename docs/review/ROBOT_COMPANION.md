# 히어로 로봇 동행(도크) 설계

기준일 2026-10-09. 문제는 하나입니다. 히어로 pin이 풀리면 조립을 마친 로봇이 섹션과 함께 위로 밀려 나가고, 이후 여섯 섹션에서 다시 나오지 않습니다. 페이지 전체가 이 로봇 한 대를 해부하는 문서인데, 정작 로봇은 첫 화면에만 머뭅니다.

## 1. 결론

**같은 로봇이 화면 오른쪽 아래로 걸어 내려와 문서 끝까지 동행합니다.** 새 모델을 띄우지 않고, 히어로의 WebGL 캔버스와 카메라를 그대로 씁니다. 크기와 위치만 스크롤에 묶어 옮깁니다.

| 구간 | 로봇 | 사용자가 할 수 있는 일 |
|---|---|---|
| 히어로 pin (기존) | 조립, 완성, 드래그 회전 | 그대로 |
| 히어로 이탈 (화면 높이 70%) | 바닥 격자가 발밑으로 접히고, 로봇이 줄어들며 오른쪽 아래로 이동 | 스크롤을 되돌리면 역재생 |
| 도크 (02~07, 푸터) | 작은 로봇이 커서를 보고, 스크롤 속도에 무릎으로 반응하고, 섹션이 바뀌면 본문 쪽을 한 번 봄 | 드래그 회전, 클릭하면 완성 화면으로 복귀, 접기 |
| 해부도(02) | 부품표나 번호 풍선을 가리키면 해당 3D 부품이 X선처럼 빛남 | 2D 도면과 3D 실물을 함께 읽음 |

## 2. 5인 검토 (BLACK 초안 → 비평 → 반영)

**BLACK 초안.** 히어로 이탈 진행률 e로 로봇을 히어로 위치에서 도크 위치로 보간합니다. 캔버스는 이탈 중 화면 전체 고정, 도착하면 도크 크기로 줄입니다. 카메라 `setViewOffset`의 부분 창으로 같은 프레임의 일부만 그리므로 전환 순간 픽셀이 튀지 않습니다.

**RED 이성.** "남아 있다"만으로는 장식입니다. 할 일이 있어야 합니다. 도크의 일은 세 가지로 한정합니다. (1) 같은 로봇이라는 연속성, (2) 해부도에서 2D 부품표와 3D 실물의 연결, (3) 3D 화면으로 돌아가는 길. 03~07에는 기능을 지어내지 않고 시선과 자세 반응만 둡니다.
→ 반영: 섹션별 대사, 말풍선, 가짜 수치 없음.

**SILVER 3D·웹 전문가.** 도크에서 전체 화면을 계속 렌더하면 낭비입니다. 도착 후에는 렌더러를 도크 크기로 줄이고, 같은 원근을 유지하려면 가상 전체 프레임 기준 `setViewOffset`을 씁니다. `#hero`는 `isolation:isolate`라 안쪽 고정 요소가 뒤 섹션에 깔리므로 도크는 body 직속(`#hero-dock`)에 둡니다. 히어로가 화면 밖일 때 루프를 멈추던 IntersectionObserver는 도크가 펼쳐져 있으면 계속 돌게 바꿉니다. 접으면 렌더를 멈춥니다.
→ 반영: 전부 적용. 도크에서는 2048px 그림자 맵을 매 프레임이 아니라 약 10fps로 갱신합니다.

**BLUE 공감.** 긴 글과 차트를 읽는 동안 시야 가장자리에서 계속 움직이면 방해됩니다. 상시 움직임은 숨쉬기와 시선 정도로 낮추고, 큰 동작은 사건(섹션 전환, 부품 선택)에만 둡니다. 거슬리는 사람을 위해 접기 버튼을 두고 선택을 기억합니다. 모바일은 본문을 가리므로 더 작게 둡니다.
→ 반영: 접기(localStorage, 실패해도 동작). 데스크톱은 1360px 본문 오른쪽 여백에 맞춰 높이 160~236px로 크기를 정해 본문을 가리지 않습니다(1440px 화면 236px, 1280px 화면 160px). 모바일은 84×132px.

**GOLD 독자 (노트북으로 읽는 경영 리더).** "부품표에서 배터리를 가리켰더니 오른쪽 아래 로봇 몸통 안이 빛났다. 그때 도면이 이해됐다." 장난감 같은 손 흔들기나 점프는 원하지 않습니다. 기존 취향 기준(고급 사실감, 라벨은 호버 시에만)과도 맞아야 합니다.
→ 반영: 도크 꼬리표(섹션 도면 번호와 조작 안내)는 호버 때만 표시. 과장된 제스처 없음.

## 2-1. 동작 추가 (2026-10-09, 사용자 피드백 "너무 가만히 있다")

도크 로봇이 서 있기만 하면 장식으로 보입니다. 상시 움직임은 낮게 두라는 BLUE 원칙은 지키고, 멈춰 있을 때만 일을 찾게 했습니다.

| 조건 | 동작 |
|---|---|
| 처음 도크에 도착 | 왼팔로 한 번 손을 흔듭니다 |
| 커서를 도크에 올림 | 손 흔들기 (8초에 한 번) |
| 섹션이 바뀜 | 본문 쪽을 보며 오른팔로 가리킵니다 |
| 스크롤이 1.2초 멈춤 | 3~6초 간격으로 체중 이동, 둘러보기, 손 확인(손목을 뒤집어 봄), 기지개 중 하나 |
| 스크롤이 7초 멈춤 | 바닥에 앉아 팔뚝을 무릎에 올립니다. 앉은 채로 둘러보기, 손 확인, 손 흔들기를 합니다 |
| 스크롤 재개 | 하던 동작을 멈추고 빠르게 일어섭니다 (앉기 약 2초, 일어서기 약 0.7초) |

앉을 때 발은 제자리에 두고 골반이 뒤로 물러납니다. 골반 아래에 접지 그림자를 하나 더 둡니다. 동작 표는 `01-hero.html`의 `ACT_DUR`, `actArm`, `SIT`입니다.

## 3. 구현 계약

- 소유: `src/01-hero.html`. 도크 요소 `#hero-dock`은 히어로 스크립트가 body에 붙입니다. CSS 선택자는 `#hero-dock`으로 시작합니다.
- 조각 간 통신: 해부도는 `document`에 `argos:part` 이벤트(`detail: { id, on, sel }`)를 보냅니다. 전역 변수는 만들지 않습니다. 히어로가 없으면 이벤트는 그냥 버려집니다.
- 부품 대응: 해부도 id 12개를 히어로 부품 이름 규칙으로 묶습니다(`01-hero.html`의 `PART_MAP`). 해부도 id를 바꾸면 이 표도 함께 고칩니다.
- 끄는 조건: `prefers-reduced-motion`, WebGL 폴백, GSAP 없음에서는 도크를 만들지 않습니다.

## 4. 합격 기준

- 히어로 끝에서 도크까지 로봇이 끊기거나 튀지 않습니다(역스크롤 포함).
- 도크 상태에서 콘솔 에러 0, 1200px과 375px에서 가로 스크롤 없음.
- 해부도에서 부품표 12행 모두 대응 3D 부품이 빛납니다.
- 접기 후 렌더 루프가 멈춥니다.

## 5. 중단 기준

도크가 본문 읽기를 방해한다는 피드백이 두 번 이상 나오면 기본값을 접힌 상태로 바꾸고, 해부도 섹션에서만 자동으로 펼칩니다.
